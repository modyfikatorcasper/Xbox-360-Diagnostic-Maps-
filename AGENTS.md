# Agent workflow

GitHub is the shared project knowledge base: code, ideas, decisions, workflow and verification status.

- Before EACH module/task and again before the final build or delivery, inspect current remote changes, README.md, docs/PROJECT_TREE.md, docs/IDEAS_BACKLOG.md and relevant module documentation. Incorporate newly recorded requirements; do not rely only on conversation memory.
- Preserve other contributors' work and uncommitted changes. Do not overwrite remote changes or force-push to bypass conflicts.
- An explicit user request to save, commit or push project work to GitHub is authorization to complete that operation. Do not repeatedly ask whether to perform the same authorized action. Act autonomously within scope; report concrete access failures or actual platform approval requirements accurately. Never bypass access controls.
- After work, update documentation with implemented items, actual tests, unresolved issues, commit and working preview URL when applicable. A successful build or push alone does not establish a working deployed application.
- Read the current ideas backlog before implementing. Items marked future/IDEA are not automatically authorized for implementation.
- New repositories are private by default. Existing repository visibility stays unchanged unless specifically authorized. Public application access and source repository access are separate decisions. Do not post promotional messages without explicit authorization.
- Preserve source attribution and actual licenses. Do not invent diagnostic values, verified cases, pinouts or licenses.

Current priorities and acceptance criteria: docs/IDEAS_BACKLOG.md, section dated 2026-10-10.
